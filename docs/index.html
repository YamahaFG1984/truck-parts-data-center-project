卡车配件 AI 产品数据中心 · MVP

把散落在供应商 Excel、PDF 和照片里的卡车配件数据，整理成一份标准、可追溯的产品数据库，让销售在几秒内回答客户的"这是什么件、能不能配、多少钱"。

Django 5.2 · PostgreSQL 16 · HTMX · 国内 OpenAI 兼容大模型接口 · 文档版本 v1.0 · 2026-09-18

项目定位。这是一个用于向公司总经理演示的最小可行产品（MVP），目标是证明三件事：理解卡车配件行业的数据（OE 号、Cross Reference、适配车型、供应商）；能把岗位职责落成可运行的工作流；清楚 AI 在数据工作中的边界，即 AI 负责提取、映射与文案，匹配永远基于自家数据库，AI 产出永远先进待审核。

文档导航

产品需求文档（PRD）

产品经理视角。背景与目标、岗位职责与功能对照表、用户角色、八个核心功能的用户故事与验收标准、非功能需求、范围边界、成功指标、演示脚本。

系统设计文档

架构师视角。总体架构、技术选型与取舍、Two Scoops 项目布局、Django 5.2 实践清单、数据模型与 ER 图、核心服务设计、关键流程、数据治理、测试、CI、部署、提示词附录。

标准字段规范（数据字典）

产品数据的每一个字段：类型、格式、必填级别、脏数据形态与清洗规则；各品牌 OE 号格式；供应商表头同义词表。这是岗位最核心的交付物。

施工进度表

20 个里程碑，每个里程碑一次 git 提交、一次代码审核。每项含文件清单、验收命令、审核清单、推荐执行模型，以及给接手模型的驱动提示词。

发布到 GitHub Pages

  1. 仓库推送到 GitHub 后，进入 Settings → Pages。
  2. Source 选择 "Deploy from a branch"，Branch 选 main，目录选 /docs，保存。
  3. 约一分钟后访问 https://<用户名>.github.io/<仓库名>/。所有文档使用相对链接，无需额外配置。

本地预览：在仓库根目录运行下面的命令，然后打开 http://localhost:8000/docs/。

python3 -m http.server 8000
