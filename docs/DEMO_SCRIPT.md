# 5 分钟演示脚本

给总经理演示用的逐步操作稿。每一步都写清楚**点哪里、输入什么、说什么**。
全程 `LLM_PROVIDER=mock`，断网也能走完；匹配、评分、报价、导出都是真实计算，只有 AI 的三处输出是固定示例。

## 开演前（2 分钟，客人到之前做完）

```bash
bash scripts/demo_up.sh --reset      # 数据库、演示数据、演示账号、后台任务、服务器
```

- 浏览器打开 http://127.0.0.1:8000/ ，用 `demo / demo12345` 登录，保持在首页。
- 另开一个标签页停在 http://127.0.0.1:8000/import/ （导入向导），省掉现场找入口的时间。
- 确认桌面能找到 `media/demo/supplier_quote_messy.xlsx`（`seed_demo` 生成的乱格式报价单）。
- 准备一张刹车片/制动气室的照片（演示模式下识别结果固定，照片内容不影响流程）。
- 检查页面底部有「演示数据均为合成」的声明——这句话要主动讲。

> 下面写到的数字来自默认种子（`seed_demo` 不带参数，400 个 SKU）。换 `--seed` 或做过导入后会变，开演前扫一眼首页对一下。

---

## 1. 痛点复述（30 秒）· 首页 + 看板

打开 **首页**，指着四个数字说：

> 这是按你说的情况造的一批数据：400 个 SKU，平均完整度 71 分，还有 10 组疑似重复。

点 **看板**（`/quality/`），指着「缺失项」那一列：

> 44% 缺互换号、三成缺主图、四分之一缺 OE 号——这就是今天分散在 Excel 和微信里的真实状态。
> 每个数字都能点开看到具体是哪些 SKU，这是后面所有工作的起点。

点一下「缺主图」，让它跳到产品列表，再点浏览器后退。

## 2. 导入（60 秒）· 一份乱格式报价单

进 **导入** → 选文件 `media/demo/supplier_quote_messy.xlsx` → 供应商选任意一家 → 上传。

> 这份表是故意做乱的：公司抬头占了两行、列名是 "Part No." "OEM NO" "Ref"、价格里混着货币符号。

- **预览**页：指出系统自己找到了真正的表头行。
- **列映射**页：系统已经猜好了每一列对应哪个标准字段（同义词表命中的显示"同义词"，其余走 AI）。
  手动把一列改成「互换号 Cross」，说明**机器只是建议，最终由人确认**。
- 点 **预检**：新增 / 更新 / 疑似重复 / 无效 四类数量一目了然，此时**数据库还没有被写入**。
- 点 **执行导入**：一个事务写入，结果页给出每一类的明细。

回到 **看板** 刷新：

> 报价条数和完整度立刻变了，这就是"资料进系统"的意义。

## 3. 查询（60 秒）· 客户给什么就输什么

回 **首页**，在搜索框里依次输入（一个一个来，边打边出结果）：

| 输入 | 现场要说的 |
|---|---|
| `4020269` | 精确命中 `FIT-FFL-00027`，三家供应商成本 22.90 / 23.72 / 26.90，建议售价 28.63（成本 × 1.25） |
| `4020-269` | 客户随手带横杠，仍然命中，标签变成「归一化」 |
| `４０２０２６９` | 全角输入（客户从网页复制的常见形态），照样命中 |
| `402026` | 少打一位，走前缀/模糊匹配，给出候选而不是空白 |
| `1030891` | 一个号挂在两个 SKU 上：`FIT-SHK-00040` 和 `FIT-TRB-00024`，这就是"替代件" |
| `brake chamber volvo` | 没有编号，用英文品名 + 车型也能找 |

点开 `FIT-FFL-00027` 的详情页：

> 一个页面上就是客户要的全部答案：图片、规格、OE 与互换号、适配车型、三家成本、建议售价、替代件。
> 右上角显示完整度 100 分——**数据完整度直接决定回复质量**。

## 4. 图片（60 秒）· 从照片到报价单

**搜索页** → 「没有编号？用照片查询」→ 上传照片。

> 三种方式：点击选文件、拖进虚线框，或者**直接 Ctrl+V 粘贴**——客户在微信里发来的图，复制之后贴进来就能查，演示时用这个最顺。

> 视觉模型只做两件事：认出这是什么零件、读出图上的编号。**它不负责判断是哪个 SKU**，
> 读到的编号回到我们自己的库里检索——所以结果永远可解释，不会凭空编一个号出来。

- 识别结果显示零件类型、可见编号、置信度；候选列表是真实检索出来的。
- 点 **确认是这个产品** → 记录状态变成「已确认产品」。
- 点 **生成报价单** → 数量填 `50`，毛利率保持 `25.00` → 加入报价单。
- 点 **下载 Excel**：打开给他看——图片、规格、包装、替代件、金额都在里面，
  还有一张单独的 **Internal** 表放成本和供应商，**这张表只给内部角色看，发给客户的是第一张**。

## 5. AI 补全与上架（60 秒）· AI 只建议，人来定

搜索 `FIT-BPD-00019`（一个缺英文描述、缺分类的刹车片）→ 进详情页 → 点 **AI 补全**。

> 演示模式下 AI 返回的是一条固定的刹车片文案，所以这一步要挑刹车片类的 SKU，内容才对得上；接上真实模型后任何 SKU 都可以。

> 给模型的只有这个产品的公开信息：品名、分类、编号、适配。**成本、供应商、客户信息一律不进提示词。**

- 生成的标题、描述、关键词、卖点、FAQ 出现在「待审核」卡片里，逐项带勾选框；
  会覆盖已有值的字段**默认不勾**，并标着「会覆盖当前值」。
- 勾选要的字段 → **采纳** → 回到详情页，字段已写入，来源标成 `ai`，完整度重算。
- 进 **审核台**（`/ai/review/`）看一眼历史：每条建议对应一次模型调用记录，可追溯。

再去 **产品列表** → 筛选「已上架」→ 勾选几个 SKU → 右侧「上架导出」选 **Alibaba** → **导出 CSV**。

> 没审核或缺主图的 SKU 会被自动挡住，并在页面顶部告诉你是哪几个、为什么。
> 用 Excel 打开导出的文件：中文不乱码，列顺序就是平台模板；成本和供应商不在里面。

（时间够的话）产品列表勾 20 个 → **批量 AI 补全** → 进度条实时走动：

> 批量任务在后台跑，页面不卡；结果同样进审核台，人过一遍才生效。

## 6. 收尾（30 秒）

> 今天看到的是一周做出来的 MVP，数据是合成的，但流程是真的：
> **导入 → 标准化 → 检索 → 报价 → 上架**，每一步 AI 都只在"提建议"的位置，人始终有最后一票。
> 下一步要真正落地，需要三件事：真实数据的一次性清洗、接上公司的模型账号、以及谁来维护标准字段。

## 常见追问的一句话答案

| 追问 | 回答 |
|---|---|
| 准确率多少？ | 编号匹配是数据库检索，命中就是 100% 准确；模糊匹配和图片识别给候选由人确认，所以不会答错，只会答"不确定"。 |
| AI 会不会编号码？ | 不会进业务字段。AI 的输出只能通过审核台的「采纳」写入，代码里只有这一条路径。 |
| 成本会不会泄露给客户？ | 报价单的成本在单独的 Internal 表，平台导出文件里完全没有成本和供应商。 |
| 断网能用吗？ | 现在演示的就是断网模式，AI 三处输出是固定示例，其余全部是本机真实计算。 |
| 多久能上线？ | 数据清洗和字段标准是大头，系统本身一周已可用；接真实模型只改 `.env` 里四个变量。 |

## 出问题时的退路

| 现象 | 处理 |
|---|---|
| 页面报「后台任务未运行」 | 另开终端 `python manage.py qcluster`；或跳过批量演示，单个补全是同步的。 |
| 端口被占 | `PORT=8001 bash scripts/demo_up.sh`。 |
| 数据被现场操作改乱 | `python manage.py seed_demo --reset` 一条命令回到初始状态（约 20 秒）。 |
| 导入向导卡在列映射 | 手动选字段即可，AI 只是建议；`LLM_PROVIDER=mock` 时用的是同义词表。 |

# 第二阶段：可追溯归档与归一化

给评审演示"供应商资料 → 可追溯档案 → 人工确认的归一 → 三份导出"。说明文档见
[docs/archive-guide.html](archive-guide.html)。下文的样例全部是合成数据；公司提供的资料放在 `extra/`，不进仓库。

## 开演前

```bash
bash scripts/archive_demo.sh --synthetic   # 空库 → 导入 X、Y 两份合成资料 → 匹配 → 导出到 demo-output/
bash scripts/archive_demo.sh               # 有 extra/ 公司样例时用它，结果写到 extra/output/
```

脚本最后会打印一条 `DATABASE_URL=… manage.py runserver` 命令：用它启动服务器，页面上就是这批数据。
登录 `archive_demo / archive-demo-local`（仅本机）。陌生资料在 `demo-output/samples/03`–`05`。

## 1. 结果先看（1 分钟）· 三份导出

- 打开 `demo-output/主数据.xlsx`：一行一个产品，成员不一致的字段写"冲突：…"，最后一列是每个成员的文件与定位。
- `供应商报价.xlsx`：GBP、EUR、USD 各自原样，缺币种的是空格，不是 USD。
- `待人工确认清单.xlsx`：每条都有触发原因、冲突两边取值、建议动作。

**说**：机器只提出"可能是同一件"并摆出证据，归一全部由人点。

## 2. 复核（2 分钟）· `/archive/review/`

- 强证据一组：勾选 → 批量确认（每条单独进日志）。
- 位置冲突（共享 OE、左右不同）：打开对照页，冲突标红，每个值下方是列名、单元格、原文 → 判为不同。
- 合并错了：对照页底部"移出"，相关配对重新进入待确认。

## 3. 陌生资料演练（每一处人工步骤的入口）

| 步骤 | 资料 | 做法 | 人工入口 |
|---|---|---|---|
| a | `03_supplier_z_offer.xlsx`（新供应商，标题行在表头上方，`Item Code`、`L/R` 两列不在同义词表，尺寸是 mm） | 页面：资料归档 → 上传 → 列映射页把两列分别选为"供应商料号 / 品牌号""安装位置"。命令：`archive_import … --supplier "Supplier Z"` 先预检，看到两列是 `ignore` 和"没有供应商料号列"的警告，再加 `--map "Item Code=supplier_sku" --map "L/R=position" --commit` | 列映射页 / `--map` |
| b | 同上，预检 | 看 mm → cm 的换算、`R` → Right、GBP 原样 | 预检页"确认入库"按钮 / `--commit` |
| c | `04_supplier_w_catalog.pdf`（PDF 表格） | 上传后工作表名是"表1（第1页）"，定位为 `P1/T1/R2`；缺价格、币种的行进"待补充" | 同 a、b |
| d | `05_supplier_x_update.xlsx`（X 的新一版） | 预检逐行显示：报价更新 1、资料更新 1、关键字段变化 1（位置 Left → Right）、新增 1、未变 7、本次未出现 1 | 预检页确认 |
| e | 关键字段变化 | 若 X-002 已与别家归一，成员关系暂停，复核台出现"关键字段变化"条目（新版本 vs 旧版本）→ 保留或移出 | 复核台 |
| f | 查询 | `/archive/` 输入 `oe tst 1001`、`side grille`、`Supplier Z`；点产品看成员报价与出处，点记录看整行原文与"相似但未配对"提示 | 档案查询 |
| g | 导出 | 档案查询页底部三个按钮，或 `archive_export --out 目录` | — |

命令行版（在 `archive_demo.sh` 生成的库上）：

```bash
export DATABASE_URL=sqlite:///$PWD/demo-output/archive_demo.sqlite3
S=demo-output/samples
python manage.py archive_import $S/03_supplier_z_offer.xlsx --supplier "Supplier Z" --user archive_demo
python manage.py archive_import $S/03_supplier_z_offer.xlsx --supplier "Supplier Z" --user archive_demo \
  --map "Item Code=supplier_sku" --map "L/R=position" --commit
python manage.py archive_import $S/04_supplier_w_catalog.pdf --supplier "Supplier W" --user archive_demo --commit
python manage.py archive_import $S/05_supplier_x_update.xlsx --supplier "Supplier X" --user archive_demo --commit
python manage.py archive_export --out demo-output/after-rehearsal
```

## 4. 现场拿到真正没见过的资料

1. 资料归档页上传（或 `archive_import 文件 --supplier 名称`，不加 `--commit`）。解析失败时原件照样存档，详情页写明原因。
2. 列映射：同义词认不出的列先看大模型建议（`.env` 配了真实模型时）；不对就手选，至少要有料号、OE 或品名之一。
3. 预检：看警告（币种与格式矛盾、无单位尺寸、缺年份）和缺失，确认后入库。
4. 复核台处理新出现的条目；导出三份结果。
5. 品类不在词表里：先照原文入库；会后补 `vocabulary.json`，`archive_rematch --restandardize` 预演、`--commit` 生效。

## 常见追问

| 问题 | 一句话 |
|---|---|
| 为什么不自动合并强证据？ | 需求明确"不能只凭共享 OE 合并"；强证据只是排在前面、可批量确认，每条仍记人和时间。 |
| 原件改过怎么办？ | 原件不改；新文件是新的存档，逐行对比出新版本，旧版本保留。 |
| 两家报价币种不同能比价吗？ | 不换算、不比较；产品页并列展示原币种报价。 |
| 词表或规则改了，旧数据怎么办？ | `archive_rematch --restandardize` 从原件重算，变化写成新版本；已做的决定证据不变就不动。 |
