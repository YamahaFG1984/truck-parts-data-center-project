1. 使用说明

必填级别含义对完整度的影响
必填缺失则记录无效，导入时跳过并记录原因无法入库
推荐可入库，但计入完整度缺失项按权重扣分
可选锦上添花不扣分

来源优先级（同一字段多来源冲突时）：人工确认（verified）> 人工录入（manual）> 供应商文件导入（import）> AI 建议（ai）。低优先级来源不覆盖高优先级已有值，只补空。

命名约定：数据库与代码使用英文 snake_case；界面显示中文；导出到平台时按平台模板改名。

3. PartNumber 编号

字段中文类型级别格式规则示例常见脏数据清洗规则
part所属 SKUFK Part必填————
number编号原文char(64)必填保留供应商或车厂的书写格式A 000 420 15 20多个编号挤在一格（"20443906/20568713"、换行、中文顿号）按 / , ; 、 换行 | 拆分为多条
number_norm归一化编号char(64) 索引系统去除所有非字母数字、转大写A0004201520—由 normalize_number 生成，禁止手工填写
kind编号类型enum必填OE 主机厂原厂号；CROSS 其他品牌互换号；SUPPLIER 供应商料号OEOE 与 Cross 混在同一列按 brand 是否为整车厂判断；无法判断时按列映射默认值并标 confidence 0.6
brand编号所属品牌FK Brand，可空推荐整车厂或零部件品牌Volvo拼写变体 "VOLVO"、"沃尔沃"、"Volvo Trucks"品牌别名表归一
source / confidence / verified——系统AI 提取的编号 confidence ≤ 0.8 且 verified=false———

唯一约束：(number_norm, kind, brand)。同号出现在多个 SKU 上不在库级阻止，进入疑似重复列表。

12. 合成演示数据规范

seed_demo 命令生成的数据必须遵守本字典的格式，并按下面的比例混入脏数据，让看板与清洗功能有东西可展示。所有编号按第 9 节的格式规律随机生成，并在 README 与页面页脚注明"演示数据，非真实 OE 号"。

项规范
规模约 400 个 Part，12 个叶子分类，18 个品牌（10 整车厂 + 8 零部件），6 个供应商，约 1200 条 PartNumber，约 600 条 Fitment，约 500 条 SupplierOffer
Cross 关系约 30% 的 Part 有 Renault ↔ Volvo 形式的 Cross（74 + Volvo 号）；约 40% 有零部件品牌 Cross
缺失35% 无主图；25% 无 OE；20% 无分类；30% 无适配；25% 无报价；15% 无英文描述
脏格式20% 的 PartNumber.number 带空格或横杠；5% 全角；5% 小写
重复10 组"同一 OE 指向两个 SKU"的疑似重复
状态60% draft、30% reviewed、10% published
图片用 Pillow 生成带分类名与 SKU 文字的占位图，尺寸 800×600，不下载外部图片
乱格式 Excelscripts/make_supplier_excel.py 生成 media/demo/supplier_quote_messy.xlsx：前两行公司抬头、表头为 "Part No. / OEM NO / Ref / Description / 适用车型 / MOQ / FOB Price(USD) / Packing"、约 80 行，其中 10 行与库内 SKU 重复、5 行编号格式脏、3 行缺 OE、2 行价格带币种符号
标准字段规范 v1.0 · 品牌编号格式仅为经验规律，演示数据均为合成，编号不代表真实 OE 号。
