零件资料的可追溯归档与归一化 · 交付说明

把不同供应商、格式各异的零件报价资料（Excel、CSV、PDF）整理成可查询、可核对、可导出的产品档案。原件永不覆盖，每个字段都能回看到原件的哪一格，"是不是同一个产品"一律由人决定，新资料进来能分清新增、更新与冲突。

4. 疑似同一的依据

先召回、再判定、最后交人。召回只有三条路：共享 OE / 互换号（至少 5 位）；同品类 + 同适配车型；完全没有适配的记录用同品类 + 同位置 + 同尺寸。判定按顺序看：品类 → 位置 → 两边 OE 都有但无一相同 → 缺失 → 适配、年份、尺寸 → 共享编号 → 是否同一供应商。

类别典型情形建议动作（写在条目上）
强证据疑似同一共享 OE，品类、位置、适配、尺寸都一致核对后确认同一；可勾选批量确认，每条单独记日志
无编号佐证品类、适配、尺寸一致，但没有共享编号对照图片或目录再定
同源重复同一供应商内两条几乎相同向供应商确认是否重复报价
编号冲突共享 OE，但品类不同（如格栅与防虫网）多半是互换号引用不严，通常判为不同
位置冲突共享 OE，但左右不同左右件通常是两个产品
信息不足一边缺适配或尺寸，无法比较补资料后再判
待补充（单条）缺品类、适配、尺寸、价格、币种等关键字段标记待补充或确认独立
关键字段变化（单条）新版本改了品类、位置、适配、尺寸或 OE保留在原产品，或移出成新产品

硬约束：短编号相近、尺寸相同、名称相似、共享 OE——任何单一信号都不会导致合并。所有合并都要人点；合并可撤销；判为"不同"的两条不会被后续合并绕过。不成对的相似记录（同尺寸不同品类、左右不同、OE 均不相同）在记录页给出一句说明。

5. 出处如何留存

  • 原件：按上传字节原样存档（文件只读），记 sha256；同一供应商重复上传同一文件会被拦下并指向已有记录。
  • 行：每条来源记录带定位——Excel / CSV 为"工作表!R行号"，PDF 为"P页/T表/R行"——以及整行原文和每个单元格坐标。
  • 字段：每个标准字段存 {值, 规则, 警告, 出处[列名, 单元格, 原文]}。例如尺寸"1220 x 750 x 70（表头注明 mm）"存为 122 × 75 × 7 cm，规则写明换算，原文照留。
  • 不猜：币种缺了就是缺，不默认 USD；单元格格式显示 $ 而币种列写 EUR 时以币种列为准并警告；无单位的尺寸不换算。
  • 版本：更新写成新版本并指向上一版，旧版本一行不改；记录页能看到整条版本链。
  • 决定：每次归一、拆分、判不同、选定取值都写决策日志（人、时间、依据）。
  • 导出：三份 xlsx 的每一行都带文件名与定位，能追回原件的那一行。

6. 哪些自动、哪些人工

系统自动做必须由人做
原件存档与去重；解析与定位；列映射建议；字段标准化、单位换算与警告；出处记录；版本对比；候选召回、分类、证据整理与建议动作；查询；三份导出确认列映射；确认入库；所有归一、拆分、判为不同的决定；成员取值冲突时选定取值；关键字段变化后保留或移出；补充缺失信息；规则调整

大模型只在一处出现：同义词表认不出的列名，给出映射建议（只发送表头和 3 行样例），仍需人确认。匹配与归一不调用大模型。

7. 如何持续维护

  • 增量导入：同一供应商的新文件逐行与其当前版本对比，分为新增、未变（不重复写入）、报价更新、资料更新、关键字段变化，外加"本次未出现"（只提示不删除）。报价、资料更新时归一关系延续；关键字段变化时暂停该成员并生成复核条目。
  • 新供应商 / 新格式：首次确认的列映射存为该供应商模板，下次同表头文件自动沿用。
  • 规则调整：品类词表在 apps/sources/rules/vocabulary.json，匹配参数与建议动作在 apps/archive/rules/matching.json。改完先预演 archive_rematch --restandardize，确认后加 --commit：从原件重新推导字段，结果变化的写成"规则重算"新版本；已决条目证据不变就保持，证据变了自动重开。
  • 人工确认回写：复核台上的决定即时生效并入日志；再导入、再匹配都会沿用，不会被机器推翻。

9. 局限与不做的事

  • 不做汇率换算；不做扫描件 OCR；不凭图片判断是否同一件。
  • 没有表格线也对不齐的 PDF 会标为"无法识别表格"，原件保留、提示人工处理。
  • 入库后匹配是全量重算（结果幂等、保留条目编号），目前规模足够；数据量大后再改成只算变化的记录。
  • 品类词表需要持续补充；未登记的品类保留原文并警告。
